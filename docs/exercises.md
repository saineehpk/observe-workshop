# แบบฝึกหัด

ทุกข้อใช้ stack ในเครื่อง (`make start`) และใช้ Claude ได้เต็มที่
ตอบโดยติดป้ายหลักฐานทุกข้อ: **Observed** (เห็นใน log/metric/trace) · **Inferred** (อนุมาน) · **Unknown**

## เริ่มแต่ละข้อด้วย `make exN`

ระบบจำลองมี 3 เว็บ แต่ละเว็บคือ 1 namespace: `web-alpha`, `web-bravo`, `web-charlie`
username ขึ้นต้นด้วยชื่อเว็บแล้วตามด้วยเลข เช่น `alpha0004`, `bravo0006`, `charlie0005` (เว็บละ 0001–0050)
กรองด้วย `namespace` ของเว็บนั้นก่อน แล้วค่อยกรอง username จะได้ query ที่แคบและเร็ว

`make ex2` (หรือ ex1, ex3, ex4) จะคืนยอดเงินทุกเว็บ จำลองเหตุการณ์ แล้วพิมพ์ **ticket** แบบที่ Support ส่งมา:
ชื่อเว็บ · username · เวลาโดยประมาณ · อาการ ไม่มี trace_id ให้ หาเองจาก namespace + username + เวลา
พร้อม prompt สำหรับ Claude ที่ก๊อปไปวางได้เลย หาไม่เจอให้รัน `make hint` จะได้ trace_id และ query

รันซ้ำกี่รอบก็ได้ ทุกรอบเริ่มจากสถานะเดียวกัน

---

## ข้อ 1 · log แบบเก่า vs business record (20 นาที)

1. `make ex1` (สลับเป็น log แบบเก่าให้เอง) แล้วอ่าน ticket
2. ใช้แค่ log ใน Loki ตอบ 4 ข้อของผู้เล่นใน ticket: พังขั้นไหน / เพราะอะไร / เงินขยับไหม / ผู้เล่นได้คำตอบอะไร
3. `make ex1-business` เคสเดิมในโหมด business record ตอบ 4 ข้อเดิม
4. เขียนสั้นๆ ว่า field ไหนทำให้ตอบได้ และโหมด legacy ขาดอะไร

## ข้อ 2 · "เกิดข้อผิดพลาด" ตอนย้ายกระเป๋า (30 นาที)

1. `make ex2` แล้วหา record ของคำขอใน ticket (ใบ้: บรรทัดที่ได้ HTTP 500)
2. record บอกว่า `persistence_error` และ `money_effect=unknown` ป้ายนี้ถูกไหม เงินขยับจริงหรือเปล่า ใช้หลักฐานอะไรยืนยัน
3. ต้นเหตุคืออะไร (ใบ้: ลองย้ายยอดเท่าเดิมซ้ำ กับยอดต่างกัน แล้วดูเวลา)
4. แก้ `app/api.go` ให้เคสนี้มี `error_class` ที่บอกสาเหตุ และ `money_effect` ที่ถูก
   อย่าลืมเพิ่มค่าใหม่ใน `knownErrorClasses` (`app/observe.go`) ไม่งั้น metric จะเห็นเป็น `other`
5. `docker compose up -d --build api-alpha api-bravo api-charlie` แล้ว `make ex2` ยืนยันผล
6. คุยกัน: เคสนี้เกิดได้ทุกเว็บไหม ข้อความที่ผู้เล่นเห็นควรเปลี่ยนไหม ใครควรเป็นคนตัดสิน

## ข้อ 3 · เช็คอินรับได้สองครั้ง (30 นาที)

1. `make ex3` ticket มาจากทีมบัญชี: ผู้เล่นรับรางวัลได้สองครั้งในวันเดียว
2. หา trace ของการกดครั้งแรก ไล่ทุก record ที่เกิดขึ้น เรียงตามเวลา (เปิดใน Tempo ด้วย)
3. ค่า stack ถูกเปลี่ยนจาก `-1` กลับเป็นค่าอื่นตอนไหน โดยใคร เพราะอ่านค่ามาจากไหน
4. ผู้เล่นบนเว็บอื่นกดสองครั้งแล้วเป็นแบบนี้ไหม (ลอง `SITE=web-alpha make s03`) ทำไมเกิดแค่บางเว็บ
5. ถ้าเหตุการณ์นี้เกิดบน prod แค่ 0.1% ของคำขอ จะเห็นได้จาก metric ไหม ถ้าไม่ได้ ต้องเพิ่มอะไร
   (เช่น record หรือ field ที่บอกว่า consumer เขียนทับสถานะ "รับแล้ว")
6. ลงมือเพิ่ม rebuild แบบข้อ 2 แล้วรัน `make ex3` ให้เห็น

## ข้อ 4 · ถอนแล้ว "กำลังดำเนินการ" (25 นาที)

1. `make ex4` แล้วหาเคสใน ticket ระวังผู้เล่นคนอื่นบนเว็บเดียวกันที่ถอนในเวลาใกล้กัน
2. api บอกอะไร worker บอกอะไร ใครเป็นแหล่งความจริงเรื่องเงิน
3. field `caller_gone` บอกอะไร แล้วเปิด trace เดียวกันใน Tempo (ลิงก์ Tempo ใต้บรรทัด log)
   span ของ api กับ worker ยาวเท่าไร เรื่องเดียวกันดูจาก trace ง่ายกว่าหรือยากกว่า log
4. เขียน query (LogQL หรือ PromQL) ที่นับเคส "ฝั่ง api ไม่รู้ผล แต่ฝั่ง worker ตัดเงินแล้ว" แยกตามเว็บ
5. ออกแบบ alert: เงื่อนไข · threshold · ส่งถึงใคร · คนรับ alert ต้องทำอะไรต่อ

## ข้อ 5 · metric และอัตรา (20 นาที)

ใช้ข้อมูลที่ `make start` เติมไว้ (`seed-fast`) ถ้าไม่มี ให้รัน `make seed-fast` ใช้เวลาประมาณ 3 นาที

ใช้หน้าต่าง `[1m]` เช่น `rate(workshop_business_records_total{...}[1m])`
ช่วงผิดปกติของ `seed-fast` ยาวไม่ถึงนาที ถ้าใช้ `[5m]` ค่าจะถูกเกลี่ยจนแทบแบน และขอบเวลาจะคลาดไปหลายนาที
metric ทุกตัวมี label `namespace` (ชื่อเว็บ)

1. ให้ Claude สรุปอัตรา `outcome × error_class × money_effect` ต่อ operation ใน 15 นาทีล่าสุด
2. มีช่วงไหนที่ผิดปกติ **เว็บไหน** เริ่มกี่โมง จบกี่โมง ใช้แค่ข้อมูล ห้ามเปิด annotation
   (ลองเทียบผลของ `[1m]` กับ `[5m]` ด้วย ว่าเวลาที่ตอบได้ต่างกันเท่าไร)
3. ช่วงนั้นผู้เล่นโดนอะไร และเงินเสี่ยงกี่รายการ
4. ทำ panel ใน Grafana 1 panel ที่ตอบว่า "ตอนนี้เงินเสี่ยงอยู่กี่รายการต่อนาที แยกตามเว็บ"
5. ตรวจคำตอบข้อ 2 กับ annotation tag `spike` ใน Grafana
6. คุยกัน: ทำไมต้องดูเป็นอัตรา ไม่ใช่ยอดรวม และถ้าเพิ่ม `username` เป็น label ของ metric จะเกิดอะไร
   (`namespace` เป็น label ได้ เพราะมีไม่กี่ค่า)
7. หาเคสที่ฝั่ง api กับ worker บอกผลไม่ตรงกัน (ใบ้: worker ปฏิเสธเพราะยอดไม่พอ แต่ api ไม่รู้)

## ข้อ 6 · ออกแบบ record ให้ flow ใหม่ (30 นาที)

เลือก flow ที่ตัวเองดูแลจริง 1 flow แล้วเขียนบนกระดาษ:

- operation และ stage ทั้งหมด
- ชุดปิดของ `error_class`
- ทุกจุดที่ `money_effect` เป็น `unknown` ได้ และจะไปหาความจริงจากไหน
- field ก่อน/หลังที่ต้องมี เพื่อตอบ 4 ข้อ
- ticket แบบไหนที่ Support จะส่งมา (เว็บ + username + เวลา) และจะหา record ของเคสนั้นด้วย query อะไร
- อะไรที่ห้ามลง log (PII, token, เลขบัญชี)
